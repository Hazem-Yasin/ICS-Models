## 2. Author decisions that shape the work

- **The CRD-7 is exempt from the ICS "soft, rounded" shape language.** The author asked for a harder, denser, Alien: Isolation style industrial look and lifted the triangle budget. Other compliance tools: still undecided (CRD-7 spec, open question 9). Ask before applying the hard look to them.
- **Body is pure bare metal.** The author asked for no white lines, paint chips, scratches, tally or grime on the body. Brushed lines and panel grooves are fine. The later "story wear" is small and local, and all of it sits behind `STORY_WEAR` (see section 5).
- **"Do them all"** on my idea list produced the v4 additions. Every invented thing is tagged `[PROPOSAL]` in `_specs/CRD-7.md`. The author has not reviewed them individually, so expect cuts.

## 3. Build pipeline

Everything is generated by script. The `.blend` and `.fbx` are **build outputs**; hand edits are lost on the next rebuild. Change the script, then rebuild.

```
Weapon Models/compliance/CRD-7/CRD-7_build.py      geometry, materials, previews, export (~1,040 lines)
Weapon Models/compliance/CRD-7/crd7_textures.py    all procedural textures
Weapon Models/attachments/<ID>/<ID>_build.py       one per attachment; load the base via _shared/studio.py
_shared/studio.py                                  append_base(scene, blend, prefixes), setup(scene, floor_z), Cam.shot(path, loc, target, lens)
```

Run (Blender 5.2, from WSL):

```
"/mnt/c/Program Files/Blender Foundation/Blender 5.2/blender.exe" --background --python <script> -- "$(wslpath -w <ICS-Models root>)"
```

Build order matters: **CRD-7 first, then attachments**, because they append the base blend and read its mount empties.

Practical lessons:
- The HardOps and grid_modeler add-ons print GPU `SystemError` tracebacks on every run. They are harmless.
- Run builds in the background with output sent to a log, and wait for the line starting `exit ` in that log. A "completed" notice from a background launcher only means the wrapper shell returned, not that Blender finished.
- Three builds in one foreground shell hit the 600 s tool timeout. Run them separately in the background.
- FBX export prints `Cannot register a valid material index for 'CRD-7_steel' from 'tmp_screw' mesh`. It comes from the shared screw instances. Harmless, not fixed.
- Always tell the author to **File > Revert**, never Save, if a build output is open in Blender.
- Web search and fetch tools return API 403 in these sessions (the `claude-haiku-4-5` model is not available to the key). Shell `curl` works. Nothing about real-world references was verified online; all "Alien: Isolation" look decisions came from memory.

## 4. Conventions that held up

- Name by canon ID; materials are `<CanonID>_<part>`; the FBX goes to `Weapon Models/exports/<CanonID>.fbx`; briefs go in `_specs/`.
- Metric, 1 unit = 1 m, Z up, forward is -Y (the prongs point -Y). Pivot at grip centre (`OFFY = -0.025` in the build script; `place()` adds it).
- Modifications are separate attachments parented to a **named mount empty** on the base. Mount empties on the CRD-7: `mount_CRD-7X_emitter`, `mount_CRD-7R_battery_port`, `mount_prongs`, `mount_holster_rails`. Attachments build with their origin at the mount, so they drop in with no offset. **Never move a mount without rebuilding every attachment.** This already bit once: CRD-7R's mount moved to the port centre.
- Parts that animate (shutter, flaps, prong guard, mode wheel, plungers) are separate objects with pivots at their hinge or axle, but the poses are baked static. There is no rig.

## 5. What I learned modelling the CRD-7

### Geometry
- The helper set in `CRD-7_build.py` carries most of the work: `rbox` and `rprism` (rounded boxes; `rprism` only rounds vertical edges), `ellipsoid`, `cyl`, `sphere`, `arc`, `xz_prism` (extrude an (x, z) outline along Y, used for the dovetail rails), `plate_box` (thin printed plate with planar UVs), `hinge(ob, px, py, pz, rx_deg)` (rotate a placed object about an X-parallel hinge line), `ribbed`, `sweep`, `screw`.
- **Cut, then fill.** Pockets, slots, grooves and bores are Boolean cuts into the body (`boolean_cut`, EXACT solver, applies the modifier and deletes the cutter). The parts that live in them are built separately and sized a hair under the cut. This is what makes it read as a machined instrument rather than stickers.
- **Z-fighting and hairline gaps.** Flush emissive strips (the indicator) showed a thin edge line until they were pushed out by 0.3 mm (`-BODY_W/2 + 0.00032`). Budget a few hundredths of a millimetre for anything coplanar.
- Screws share one mesh template (`make_screw_template`/`screw`). Cheap, and it keeps the texture tidy.
- The coiled lanyard cord is about 5,600 triangles, nearly a third of the model. If a game version needs a lighter CRD-7, drop `CRD-7_lanyard_*` first (about 11.4k left).
- Static poses were chosen so every mechanism is visible in one hero shot. Flaps and guard are posed open, and the mode flag reads RANGED. For gameplay, the closed default is an open question.
- The prong guard reads as pointing forward more than flipped up in the preview. Check the hinge angle (-78° about GP_Y/GP_Z) if the author complains.

### Textures
- All textures are numpy-generated PNGs, no external image assets. Two atlases: the **body atlas** (2048 px at 12 px/mm, six tiles: top, bottom, px, mx, front, rear) and the **trim atlas** (1024 px, four 512 px swatches: 0 ABS, 1 rubber, 2 steel, 3 red plastic). Text and printed marks go through `_render_masks`, a Cycles emission render with channel packing (R = print, G = label, B = sticker). Plate/tag/tape images come from `make_plates()` at 24 px/mm.
- **Metal is a mask.** `maps["metal"]` drives Metallic, so paper, stickers, stencils and print stay non-metal while the body is metallic 1. Anything new you paint onto the body that is not metal must be added to the `nonmetal` set, or it renders as shiny paper.
- Everything on a tile is positioned in millimetres in tile space. Several collisions only showed up in renders (asset plate over the sticker, strip over the screen, grease on the LCD). Render and look after every layout change; do not trust the coordinates.
- The rail grooves forced the label, barcode and sticker inward (label 10.5–39.5 × 38–66). Moving one feature on the underside usually moves three others.
- Material alpha for the glass materials (`M_GLASS`, `M_FUSEGLASS`) may not survive the FBX export. **Not checked.** Verify in the engine, or check the FBX before relying on it.

### Story wear (`STORY_WEAR = True` in `crd7_textures.py`)
Grease smudges, scratched "R.H." initials, a mostly worn-off "PROPERTY OF ICS" stencil, an ICS-W3 paper sliver under the label. The author's "pure metal" request is the reason these are small and local, and the reason there is a single switch. Set it to False for a clean unit. The initials are a name hook the author has not approved.

### Previews and the clip
- Preview cameras go through `Cam.shot`. A camera that ends up below the floor gives a flat grey frame, so check the geometry before blaming the lighting. The clip preview did this: it hangs off the underside, so the base root is rotated π about Y and the floor and camera are placed above it.
- Dark metal (albedo ~0.2, metallic 0.9) on a flat plate renders as a black block in the studio lighting. The clip only reads once you see its profile (side shot).
- Check every preview image after a rebuild. Several faults (blank frame, clipped print, thin gaps) were invisible in the script and obvious in the picture.

### Process
- Write the spec brief first, update it **when the model changes** (this lagged behind v4 until the end of the last session), and keep `_specs/INDEX.md` and `Weapon Models/WEAPONS.md` in step.
- Counting triangles: the build prints `STATS parts=N triangles=N`. Copy those into the spec, not estimates.
- Engine-side behaviours (hum to whine on fire, LCD flicker at low capacitor, amber to red on discharge) are recorded in the spec as notes. Do not model them.

## 7. The ICS logo (brand kit)

Moved to its own folder `Logo/` on 2026-11-08, because the mark is the whole project's identity, not a weapon detail. Read `Logo/BRAND_MARK.md` first: it separates canon from `[PROPOSAL]` and lists the open questions.

```
Logo/src/ics_brand.py       the ONLY place the mark geometry lives (pure python, numpy for rasters)
Logo/src/ics_brand_bpy.py   turns it into Blender meshes (build_mark)
Logo/build_brand.py         writes Logo/svg and Logo/png (mark, variants, lockups, sheets, seal, emblem)
Logo/fonts/                 Nunito, Varela Round (OFL)
Logo/BRAND_MARK.md          canon vs proposal, files, open questions
Logo/ICS-Logo_build.py      editable 3D emblem -> Logo/ICS-Logo.blend + Logo/previews (Blender 5.2, run like the model builds)
Logo/ICS-Mark_build.py      parametric Geometry Nodes mark -> Logo/ICS-Mark.blend (sliders in the modifier panel)
Logo/ICS-Mark_params.py     run in Blender: prints the slider values as an ics_brand.py ARC dict
Logo/src/ics_seal.py        shared layout of seal and emblem (radii, per-letter ring positions, ticks, ribbon): read by build_brand.py AND ICS-Seal_build.py
Logo/ICS-Seal_build.py      builds ICS-Seal.blend and ICS-Emblem.blend on top of ICS-Mark.blend (run ICS-Mark_build.py first)
```

**ICS-Mark (2026-11-08, `[PROPOSAL]`)** is the first step of rebuilding the logo from the start: unbroken blue enamel disc, gold arc in a groove, every number a slider. Gotchas: on Blender 5.2 modifier inputs are set by socket identifier (`mod.properties.inputs[ident]["value"]`, ident from `node_group.interface`); the Boolean cutters (groove tube and end spheres) must stay two links into the multi-input `Mesh 2`, joining them first makes the disc disappear; Curve to Mesh ignores Set Curve Radius here, so the radius is a named attribute `rr` fed to its `Scale`. ICS-Seal and ICS-Emblem are now built on top of it (`ICS-Seal_build.py`, layout in `src/ics_seal.py`, 2D output verified unchanged). Still to do: static Nunito ExtraBold ring text (needs fontTools; pip install was denied in this session), game versions (high-poly, low-poly with baked maps, decal), real-size copies. Open: author rulings on text around the mark, trailer circle colour, and groove vs "unbroken circle".

- Change the arc in `ics_brand.py`, rerun `build_brand.py`, then rebuild **CRD-7 first, then CRD-7X / CRD-7R, then ACS-9**. Do not draw the mark by hand in a build script. The three build scripts add `Logo/src` to `sys.path` themselves.
- The raster helpers (`raster_mark`) are used by the ACS-9 label and were checked in the preview. `raster_wordmark` is still untested.
- Seal (`ics-seal`, `ics-seal-metal`) and emblem (`ics-emblem`, `-paper`) were added after the author's reference sheets. Ring text is set letter by letter because librsvg ignores `<textPath>`.

### Research on other logos (and its limits)
Web search returned 403 and only plain `curl` to Wikipedia worked, so **nothing here was checked against the brands' own guidelines**. The Umbrella, Diamond Dogs, XCOM, Assassin's Creed and knight crests are described from the images the author pasted. What they teach, applied in the seal and emblem:
1. A faction mark is rarely just the symbol: it sits in a **badge with concentric rings**, so one fixed circle holds the symbol and the text.
2. **Ring lettering** carries a name or motto (XCOM's "Vigilo Confido"). ICS's equivalent is the name, the Labor Source number and the tagline.
3. **Fine rim detail** (ticks, studs, hairlines) makes it feel engraved. Here the ticks are the 300 Cycles.
4. **Line-weight hierarchy**: heavy symbol, medium text, hairline rings.
5. **Metal finish** variants exist for physical props (keychain disc, badge holder, wall logo).
6. Every detail should state a fact of the world. These all do (see the table in `BRAND_MARK.md`).
The detail also costs legibility: below about 200 px use the plain mark, never the seal.
